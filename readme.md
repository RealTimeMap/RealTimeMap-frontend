# RealTime Map

Публичная карта, на которой пользователи оставляют метки с сообщениями, фотографиями и сроком жизни. Метки появляются у всех остальных в реальном времени, их можно обсуждать в комментариях и делиться ими картинкой. Вокруг карты выросло небольшое социальное приложение: профили с уровнями и достижениями, личные чаты и push-уведомления.

Работает и как веб-приложение (PWA), и как нативная сборка под Android и iOS через Capacitor.

## Возможности

**Карта и метки**

- Векторная карта с кластеризацией меток и подгрузкой по границам экрана
- Создание метки двойным касанием: категория, описание, фотографии, срок жизни
- Карточка метки с комментариями, лайками и переходом в профиль автора
- Шеринг метки картинкой — скриншот участка карты генерируется на лету
- Определение геолокации и кнопка возврата к своему положению
- 3D-здания и 3D-модели достопримечательностей

**Чаты**

- Личные переписки в реальном времени через WebSocket
- Подгрузка истории при скролле вверх
- Оптимистичная отправка: сообщение появляется мгновенно, ретрай не создаёт дублей
- Статусы «отправляется / отправлено / прочитано» и счётчики непрочитанного

**Профили**

- Свой профиль и профили других пользователей
- Уровни, опыт и достижения
- Статистика активности с тепловой картой по дням

**Приложение**

- Тёмная и светлая темы, русский и английский языки
- Онбординг при первом запуске
- Офлайн-кэш карты: в вебе через service worker, на Android и iOS через Filesystem
- Раздел «Места»: личные метки и группы, работают без сети и синхронизируются при подключении
- Автообновление Android-сборки: приложение само предлагает скачать новый APK из GitHub Releases

## Архитектура

Структура основана на [Feature-Sliced Design](https://feature-sliced.design/). Код разложен по слоям, и номер слоя задаёт направление зависимостей: слой может импортировать только слои с меньшим номером.

```
src/components/
├── 00.shared/      общее: api, services, stores, composables, lib
├── 01.kit/         UI-кит: UAvatar, UInput, UModalWrapper, USheet, …
├── 02.features/    пользовательские сценарии, разложенные по группам
│   ├── map/        карта, слои, геолокация, маршруты, офлайн
│   ├── mark/       публичные метки
│   ├── places/     личные метки и группы
│   ├── auth/       авторизация
│   ├── profile/    достижения, подписки, геймификация, поиск
│   ├── settings/   отдельные пункты настроек
│   ├── app/        обновления, пуши, уведомления, онбординг
│   └── info/       правила, документы, роадмап
├── 03.layouts/     каркасы страниц
├── 04.widgets/     крупные блоки из нескольких фич: Profile, Settings, MapControls, BottomNav, ChatList, ChatRoom, …
├── 05.pages/       страницы по разделам: map, places, chats, profile, auth
└── 06.app/         инициализация: websocket, i18n, PWA, deep links
```

Внутри каждого слайса структура одинаковая:

- **`index.ts`** — публичный API слайса;
- **`ui/`** — Vue-компоненты;
- **`model/`** — состояние, composables и типы;
- **`api/`** — собственные запросы к серверу, если они есть.

Главное правило разделения: блок, который собирает несколько фич, живёт в `04.widgets`; фича описывает одно пользовательское действие. В каждой папке слоя и группы лежит `README.md` с описанием слайсов и правил импорта.

Компоненты из `01.kit` и composables из `00.shared/api` подключаются **автоматически** — импортировать их вручную не нужно (`unplugin-vue-components` и `unplugin-auto-import`, типы генерируются в `src/types/dts/`).

## Установка и запуск

Нужны [Node.js](https://nodejs.org/) 20.19+ и [Bun](https://bun.sh/).

```sh
git clone https://github.com/RealTimeMap/RealTimeMap-frontend.git
cd RealTimeMap-frontend
bun install
```

Создайте `.env` по образцу `.env.example`:

```
VITE_API_BASE_URL=      # адрес REST API
VITE_WS_URL=            # адрес WebSocket-сервера
VITE_YANDEX_GEOCODER_KEY=   # ключ Яндекс.Геокодера для адресов меток
```

Запуск дев-сервера на `http://localhost:5173` с горячей перезагрузкой:

```sh
bun dev
```

## Команды

| Команда                     | Что делает                                                         |
| --------------------------- | ------------------------------------------------------------------ |
| `bun dev`                   | дев-сервер                                                         |
| `bun run build`             | проверка типов + продакшен-сборка в `dist/`                        |
| `bun run build-only`        | сборка без проверки типов                                          |
| `bun run typecheck`         | только проверка типов                                              |
| `bun run lint` / `lint:fix` | ESLint                                                             |
| `bun run apk-build`         | сборка веба и синхронизация с нативными проектами                  |
| `bun run bump`              | посмотреть, какой станет версия (см. [RELEASING.md](RELEASING.md)) |
| `bun run models:optimize`   | оптимизировать 3D-модели из `models-src/` в `public/models/`       |

## Мобильная сборка

```sh
bun run apk-build          # bun run build && cap sync
bunx cap open android      # открыть проект в Android Studio
```

`versionName` и `versionCode` подставляются из `package.json` автоматически — в `build.gradle` их править не нужно.

## Версии и релизы

Версия поднимается автоматически по сообщениям коммитов при попадании в `main`, руками её менять не нужно. Формат сообщений проверяется хуком при коммите.

Подробности — в [RELEASING.md](RELEASING.md): какие типы коммитов выпускают релиз, а какие нет, и как посмотреть будущую версию заранее.
